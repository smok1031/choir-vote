# 합창곡 선호도 투표

한 페이지에 주제 두 개, 주제마다 곡 다섯 개가 있고, 단원은 곡마다 1점에서 5점까지 점수를 매깁니다. 로그인 없이 링크만 열면 응답할 수 있고, 한 기기에서는 한 번만 응답할 수 있습니다. 정한 인원(기본 15명)이 모든 곡을 평가하면 조사가 닫히고, 주제별로 모든 곡의 평균 점수, 순위, 점수 분포가 공개됩니다. 그 전에는 어떤 점수도 공개되지 않습니다.

- 투표 페이지: https://smok1031.github.io/choir-vote/
- 편집 페이지: https://smok1031.github.io/choir-vote/admin.html (관리 코드 필요)

## 편집

편집 페이지에서 제목, 안내문, 주제 이름, 곡 제목, 결과 공개 인원을 고치고 저장하면 투표 페이지에 바로 반영됩니다. 관리 코드는 저장소에 두지 않고 Supabase에 해시로만 저장되어 있습니다. 코드를 바꾸려면 합창단 Supabase 프로젝트의 SQL Editor에서 실행합니다.

```sql
update public.choir_groups set admin_hash = encode(extensions.digest('새 코드', 'sha256'), 'hex') where id = 'main';
```

표가 들어온 주제는 곡 제목이 잠깁니다(표가 곡 번호로 저장되어 있어서, 바꾸면 결과가 엉뚱한 곡으로 보이기 때문). 다른 곡으로 다시 투표하려면 편집 페이지의 "새 투표 시작"을 누릅니다. 지금까지의 표와 1위가 보관함으로 옮겨지고, 모두 처음부터 다시 투표할 수 있으며, 곡 제목 칸이 다시 열립니다. 지난 회차의 1위는 편집 페이지 보관함에서, 전체 득표는 SQL Editor에서 볼 수 있습니다.

## DB 구성

합창단 전용 Supabase 프로젝트(합창단 선호도 조사)의 SQL Editor에서 `supabase/schema.sql` 전체를 실행합니다. 여러 번 실행해도 입력한 내용과 표는 지워지지 않습니다. 자주 쓰는 관리 명령은 파일 맨 아래에 있습니다.

## 한 기기 한 표의 원리와 한계

- 기기 ID: 처음 열 때 무작위 ID를 만들어 브라우저 저장소, 쿠키, IndexedDB 세 곳에 둡니다. 같은 ID는 같은 주제에 두 번 저장될 수 없습니다.
- 기기 지문: 화면 크기, OS, 그래픽 칩 등 기기 특성으로 만든 값입니다. 시크릿 창이나 다른 브라우저로 다시 투표하면 기기 ID는 새로 생기지만 지문이 같아서 "확인 필요" 표로 기록됩니다.
- 확인 필요 표를 막지 않고 표시만 하는 이유: 같은 기종, 같은 OS 버전의 휴대폰은 지문이 같게 나올 수 있어서, 막으면 정당한 다른 단원이 투표하지 못합니다. 결과 화면에 그 수가 따로 안내됩니다.
- 확인 필요 표도 공개 인원에 포함됩니다. 누군가 시크릿 창으로 한 번 더 투표하면 15명이 다 차기 전에 공개될 수 있으니, 결과 화면의 안내 문구를 확인하세요.
- 로그인이 없으므로 코드를 직접 호출해 표를 조작하는 것까지 완전히 막을 수는 없습니다. 주제당 표 상한과 IP 해시 기록으로 피해를 제한하고 찾아낼 수 있게 했습니다.
