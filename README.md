# 합창곡 선호도 투표

합창곡 다섯 곡 중 가장 부르고 싶은 곡 하나를 고르는 투표 페이지입니다. 로그인 없이 링크만 열면 투표할 수 있고, 한 기기에서는 한 번만 투표할 수 있습니다. 결과는 마감 시각이 지나야 공개됩니다.

## 처음 한 번 준비

1. Supabase 대시보드 > SQL Editor > New query 에 `supabase/schema.sql` 전체를 붙여 넣고 Run.
2. 같은 곳에서 곡 제목과 마감 시각을 넣습니다.
   ```sql
   update public.choir_polls
   set songs = '["곡1", "곡2", "곡3", "곡4", "곡5"]'::jsonb,
       close_at = '2026-11-20 22:00+09'
   where id = 'main';
   ```
3. 단원들에게 페이지 주소를 보냅니다.

곡 제목, 마감 시각, 안내문은 모두 DB에서 바꾸며 페이지를 다시 배포할 필요가 없습니다. 자주 쓰는 관리 명령은 `schema.sql` 맨 아래에 있습니다.

## 한 기기 한 표의 원리와 한계

- 기기 ID: 처음 열 때 무작위 ID를 만들어 브라우저 저장소, 쿠키, IndexedDB 세 곳에 둡니다. 같은 ID는 DB에서 두 번 저장될 수 없습니다.
- 기기 지문: 화면 크기, OS, 그래픽 칩 등 기기 특성으로 만든 값입니다. 시크릿 창이나 다른 브라우저로 다시 투표하면 기기 ID는 새로 생기지만 지문이 같아서 "확인 필요" 표로 기록됩니다.
- 확인 필요 표를 막지 않고 표시만 하는 이유: 같은 기종, 같은 OS 버전의 휴대폰(예: 같은 아이폰 모델)은 지문이 같게 나올 수 있어서, 막으면 정당한 다른 단원이 투표하지 못합니다. 결과 화면에 그 수가 따로 안내되고, 운영진은 DB에서 시각과 IP 해시를 보고 판단할 수 있습니다.
- 로그인이 없으므로 코드를 직접 호출해 표를 조작하는 것까지 완전히 막을 수는 없습니다. 투표당 최대 표 수(기본 200)와 IP 해시 기록으로 피해를 제한하고 찾아낼 수 있게 했습니다.

## 다른 투표를 추가로 열 때

`choir_polls`에 id가 다른 행을 하나 더 넣고, 주소 뒤에 `?p=그id`를 붙여 공유합니다.
